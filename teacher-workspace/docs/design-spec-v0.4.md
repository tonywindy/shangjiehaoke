> 日期：2026-07-27 ｜ 基于 v0.3 顶层设计，含 v0.4 方案变更

## 0. v0.4 相对 v0.3 的变更

| # | 变更 | 原因 |
| --- | --- | --- |
| 1 | **知识点目录改为教师上传 Excel + 自选启用**，平台不预置任何教材版本 | 零内容运营；天然适配人教/北师大/苏教及教师自定义体系 |
| 2 | 知识矩阵**默认视图改为「知识点 × 人数分布」**，学生×知识点降为下钻视图 | 60–100 个知识点的宽表必然不可用；教师日常问题是"该重讲还是小组补" |
| 3 | AI 确认队列引入**置信度分流**，高置信默认接受、只推异常项 | 把确认成本从 O(题数) 降到 O(异常数)，这是产品能否活过第二周的关键 |
| 4 | 增加**课堂快速打点**入口（选知识点 → 点没掌握的学生） | 补上"阶段 2 不依赖 AI 也能用"的缺失前提 |
| 5 | 掌握度底层存**连续值 + 证据强度**，四态是阈值映射；UI 显示证据条数 | 让"1 条证据的已掌握"和"4 条证据的已掌握"可区分，而不新增状态 |
| 6 | 复测排期由系统按**记忆衰减模型**自动生成（FSRS 思路） | v0.3 只写了"到复测时间"，未定义怎么算 |
| 7 | 作业 + 题目映射**入库为可复用资产**，跨班级跨学年复用 | 第二年零成本，长期壁垒 |
| 8 | 个性化提升项**活跃数上限 5**，AI 建议默认动作是"合并"不是"新建" | 防止碎片化成无人管理的标签堆 |

```
┌────────┬──────────────────────────────────────────────┐
│ 侧边栏  │ 顶栏：面包屑 │ 班级 │ 学科·教材 │ 单元 │ 教师  │
│ 今日 17│──────────────────────────────────────────────│

│ 学情   │                                   ┌─────────┐│

```

**全局规则**

- 顶栏的「班级 / 教材 / 单元」是全局上下文，跨页保持，切页不重置。
- **证据抽屉**是全站唯一的"为什么是这个状态"的解释器，从矩阵格子、学生清单行、补差记录三处均可唤起，内容结构完全一致。
- 侧边栏「今日」的红色角标 = 待确认总数，是教师每天回到产品的唯一理由。
- 任何页面的任何状态显示，都必须能两跳内到达原始作业与教师决策记录。

**四态色彩（全站唯一）**

| 状态 | 数据值 | 视觉 | 严禁 |
| --- | --- | --- | --- |
| 未评价 | `unassessed` | 灰色虚线圈 `·` | 计入任何百分比、参与排序打分 |
| 待提升 | `needs_support` | 红 `✕` | — |
| 基本掌握 | `developing` | 黄 `◐` | — |
| 已掌握 | `mastered` | 绿 `✓` | 系统自动降级 |

## 2. 页面一 · 今日

**回答的问题**：我现在最该做什么。

### 布局

```
[ 快速记录框：随手记一句 @学生 ]  [记录] [📷传作业]
┌──────────────────────────┬──────────────────┐
│ ① 待我确认（红标）         │ ③ 班级关注        │
│ ② 今天要做（复选清单）      │ ④ 今日动态        │
└──────────────────────────┴──────────────────┘
```

### 区块顺序不可调换

**待我确认**（有人在等我）＞ **今天要做**（我的执行）＞ **班级关注**（我的判断）。

### ① 待我确认

每条必须给出**预计耗时**和**分流结果**，否则教师不敢点进去：

> 三年级 2 班 · 第一单元练习：12 份 AI 分析待确认
> 其中 9 份高置信度可批量接受 · **3 份需要你逐个看** · 预计 4 分钟

条目类型：AI 分析待确认 / 学生姓名匹配不确定 / 个性化提升建议待确认。

### ② 今天要做

来自两大功能的统一待办，每条带来源标签（`学情` / `班级事务` / `到期`）。复测到期项自动进入此列表，教师不需要自己记。

### ③ 班级关注

**措辞铁律**：只写"证据显示"或"证据不足"，永远不写"班级没掌握"。

- 待提升占比高 → `建议全班重讲` + 分布条 + 跳矩阵
- 未评价人数多 → `证据不足，不能判断掌握情况，建议下次练习覆盖`
- 提升项超期未跟进 → 一键转教师任务

### 字段

| 区块 | 字段 |
| --- | --- |
| 待确认项 | 类型、来源任务、总数、需人工数、预计耗时、跳转目标 |
| 待办项 | 标题、来源模块、关联学生/知识点、到期标记、完成态 |
| 班级关注 | 知识点、四态人数分布、证据密度（条/人）、系统提示类型 |

## 3. 页面二 · 班级知识矩阵

**这一页的设计取舍最大，请重点评审。**

### 视图切换

```
[ 教学视图 · 知识点 × 人数分布 ]  [ 学生视图 · 学生 × 知识点 ]     □只看待提升 □只看未评价
```

#### 教学视图（默认）

一行一个知识点：

| 知识点 | 全班分布（38 人） | 证据 | 系统提示 | 操作 |
| --- | --- | --- | --- | --- |
| 2 · 一位数除法竖式 | ▓18 待提升 ▓8 基本 ▓9 掌握 ░3 未评 | 1.8 条/人 | 🔴 建议全班重讲 | 建补差任务 |
| 3 · 有余数除法验算 | ▓6 ▓10 ▓13 ░9 | 0.9 条/人 | ⚪ 证据不足 | 安排评价 |
| 4 · 倍的认识 | ░ 38 人未评价 | 0 | ⚪ 尚未教学 | 课堂快速打点 |

- **灰色（未评价）不计入百分比**，只显示绝对人数。
- **系统提示**只有四种：`整体良好` / `建议全班重讲` / `证据不足` / `N 人状态反复`。不做任何评分。
- **证据密度**（条/人）暴露"这个结论有多可信"。

**为什么默认是这个视图**：小学数学一学期 60–100 个知识点，"学生 × 知识点"表格必然横向滚动到不可用（Canvas Learning Mastery Gradebook 的经典失败）。教师 90% 的日常问题是"这个知识点全班怎么样"，教学视图直接回答。

#### 学生视图（下钻）

限定在**当前单元**内（≤10 列），支持：多选学生 → 底部浮出操作条 → 批量改状态 / 创建小组补差。点任意格子 → 证据抽屉。

### 课堂快速打点（关键）

矩阵行操作里的入口。点击后弹出全班头像墙，教师**点掉没掌握的学生** → 保存，3 秒完成一个知识点的全班评价，证据来源记为「课堂观察」。

> 没有这个入口，"阶段 2 不依赖 AI 也能用"是空话 —— 纯手工维护 100 个知识点的矩阵不会有教师真的做，而阶段 2 的失败会被误判为"AI 不够好"。

## 4. 页面三 · 学生知识清单（学生档案）

### 头部

姓名 / 班级 / 学号 + 一行本单元四态计数 + `导出该生知识清单` `生成补差题`。

**严禁**：综合评分、能力雷达图、班内排名、任何形式的性格标签。

### 五个页签

| 页签 | 内容 |
| --- | --- |
| 概览 | 今日事项、待办、最近状态变化（纯聚合） |
| 班级经历 | 班级事务时间线（表扬/活动/沟通/跟进） |
| **知识清单** | 按单元折叠，逐知识点一行 |
| **个性化提升** | 活跃项 N/5、AI 待确认建议 |
| 补差记录 | 补差任务、题量、教师改动、完成、复测、状态变化 |

### 知识清单表

| 知识点 | 当前状态 | 证据强度 | 最近评价 | 判断依据 | |
| --- | --- | --- | --- | --- | --- |
| 2 · 一位数除法竖式 | 🔴 待提升 | ●●○○ 2 条 | 7-27 | 第 2、3 题商位置写错 | 详情 |

**证据强度**是底层连续掌握度的置信度可视化，**不是第五种状态**。1 条证据和 4 条证据的"已掌握"颜色相同，但教师能一眼看出哪个结论更靠得住。

### 个性化提升

- 顶部固定显示 `活跃提升项 2 / 5`，达上限时新增需先关闭一条 —— 强制取舍。
- 超过 14 天无新证据 → `超期未跟进` 红标，并进入「今日 · 班级关注」。
- **AI 建议的默认动作是"合并到已有项"**：生成建议前先对该生已有提升项做语义检索，显示相似度；只有确无相似项才默认"新建"。
- 提升项可完全不关联知识点、不关联作业。

## 5. 页面四 · 评价任务与批量上传

### 任务列表

状态流水线：`草稿 → 上传中 → 映射待确认 → 分析中 → 待教师确认 → 已更新矩阵 → 补差已建 → 待复测 → 完成`

### 创建向导五步

```
[1 基本信息 ✓][2 上传作业 ✓][3 学生匹配 ●][4 题目→知识点映射][5 开始 AI 分析]
```

#### 第 3 步 · 学生匹配

按文件名自动匹配，**匹配不确定时系统绝不猜测**：

| 文件 | 匹配到 | 置信度 | |
| --- | --- | --- | --- |
| IMG_3391.jpg | — 请选择 — | 🔴 无匹配 | 看图 |
| IMG_3402.jpg | 李明(74%) / 李茗(71%) | 🟡 两名相近 | 看图 |
| 07_张小雨.jpg | 张小雨 | 🟢 98% | |

支持一名学生多页（`12_王浩_p1 + p2`）。未上传的学生记为**未评价，绝不记为待提升**。

#### 第 4 步 · 题目 → 知识点映射

**整份作业只确认一次，不为每个学生重复确认**（v0.3 已有的最好设计）。

| 题号 | 题目 | 对应知识点 | 确认 |
| --- | --- | --- | --- |
| 3 | 95÷4 竖式并验算 | 2、3 | ✓ |
| 7 | 妈妈买 3 盒… | 2 ? | 需确认 |

**v0.4 增强**：确认后本份作业与映射存为**可复用资源**，可跨班级、跨学年调用。第二年同一份单元练习零成本。

## 6. 页面五 · AI 分析确认 ★ 生死线

> 12 份 × 10 题 × 5 个字段 = 教师第二周弃用。这一页的效率决定产品存活。

### 三栏布局

```
┌─队列 200px──┬──作业与识别结果────────┬──AI 建议 330px──┐
│需要你看 · 3 │ 张小雨 2页10题 置信91% │ 知识状态建议     │
│ 张小雨 冲突 │ ┌────────────────┐ │ 个性化提升建议    │
│ 陈可欣 模糊 │ │ 第2题 ⚠ 答对过程错 │ │ 补差方向建议     │
│ 赵一鸣 低置 │ │ 第3题 验算未写    │ │ AI/教师留痕     │
│─────────  │ │ 第7题 缺单位     │ └────────────────┘
│高置信·已默认 │ │ 其余6题正确·折叠  │
│接受 · 9    │ └────────────────┘ │
│ 王浩 ✓ …   │ [接受全部并下一个 ⏎][逐条修改][证据不足 E]
└──────────┴────────────────────┴─────────────────┘
```

### 置信度分流规则

| 分组 | 判定 | 默认行为 |
| --- | --- | --- |
| 高置信 | 识别置信度高 + 与历史一致 + 无冲突 | **默认已接受**，折叠在队列下半区，教师可展开抽查 |
| 需要你看 | 与历史状态冲突 / 图片模糊 / 识别低置信 / 答案对但过程错 / 未作答 | 逐个推到眼前 |

顶部提供 `批量接受 9 份高置信度` 一键完成。

> 这仍然满足"只有教师确认后知识矩阵才更新" —— 批量接受也是教师的一次明确操作，且留痕。

### 必须逐条呈现的四种情形

1. **答案对但过程错**（86÷2 答 43 但商位置错）— 这是"计算失误"还是"未掌握"，只有教师能判断。
2. **未作答** — 记为证据不足，**不等于不会**。
3. **与历史冲突** — 显式提示"7-20 曾评为基本掌握"，让教师复核而非默默覆盖。
4. **图片模糊 / 识别置信低**。

### 键盘流

`J`/`K` 切学生 · `Enter` 接受并下一个 · `E` 标记证据不足 · `数字键` 定位题号。教师全程不必碰鼠标。

### 留痕

AI 原始输出与教师最终版本**分别存储**，记录模型版本号。状态变化可审计、可追溯。

## 7. 页面六 · 精准补差与复测

### 上：看板

`待生成 → 待教师确认 → 已安排 → 待复测 → 已完成`

「待复测」卡片显示到期倒计时，到期项自动进「今日 · 今天要做」。

### 中：补差题编辑

顶部固定显示**生成依据**（错误类型 + 个性化项 + 最近证据 + 教师补充），让教师知道 AI 凭什么出这些题。

三层阶梯，**每层可独立开关，不强制套用**：

| 层 | 作用 | 本例 |
| --- | --- | --- |
| ① 基础修正 | 核心概念与直接错误 | 3 题，标出商的位置 |
| ② 巩固应用 | 换数字与情境，检验稳定 | 2 题，其中 1 题**注入个性化项**（要求写完整单位） |
| ③ 迁移提升 | 变式与综合 | AI 判断本次不必要，默认关闭 |

个性化项注入是"同一知识点、不同学生题目不同"的实现方式之一：

> 两名学生同样未掌握"长方形周长"：A 混淆周长与面积 → 出对比辨析题；B 漏乘 2 → 出公式拆解 + 检查步骤题。

操作：改题干 / 换一题 / 增教师自拟题 / 学生版 PDF / 教师答案版 / 存为可复用资源。
**未经教师确认的题目不进入正式补差记录。**

### 右：复测闭环

补差前后对照表 + AI 比较结论 + 四个教师决策按钮：
`确认为基本掌握` `确认为已掌握` `保持待提升` `证据不足，暂不更新`

### 复测排期算法（v0.4 新增定义）

采用记忆衰减模型思路（FSRS：难度 / 稳定度 / 可提取性）：

- 每个「学生 × 知识点」维护稳定度 S；补差后首次复测间隔短（5–7 天）。
- 复测通过 → S 增大 → 下次间隔拉长；未通过 → S 重置 → 间隔缩短。
- 连续两次通过后自动降级为"单元末复查"，不再单独提醒。
- **「已掌握」永不自动降级**；超过预测遗忘窗口仍无新证据时，只打「证据已过期」标记，是否复测由教师决定。

### 状态变化历史

不可覆盖、不可删除，每条含：日期、新旧状态、依据（可点回原题）、确认人。

## 8. 页面七 · 知识清单导入（v0.4 新方案）

### 四步向导

```
[1 上传 Excel ✓][2 认列 ●][3 预览与勾选][4 完成]
```

#### 1 上传

拖拽区 + `下载空白模板`。模板只要三列：

| 单元 | 序号 | 知识点 |
| --- | --- | --- |
| 第一单元 乘除法初步 | 1 | 两位数乘一位数（不进位） |
| 第一单元 乘除法初步 | 2 | 一位数除法竖式 |

#### 2 认列

系统按表头猜测列用途，教师确认即可。**不要求教师改自己的表格格式** —— 教师现成的教研组清单五花八门，让系统适应人。

字段：单元列 / 知识点列 / 序号列（可选）/ 学期标识。

#### 3 预览与勾选

树形预览（单元 → 知识点），**勾选本学期真的要跟踪的**。

- 已选计数常驻：`已选 18 / 62`。没勾的不进矩阵，随时可再启用。
- 脏数据（空知识点、疑似错别字）高亮，**可直接在预览里改，不必回去改 Excel**。
- 支持一次导入应用到多个班级。

#### 4 完成 → 直接进入班级知识矩阵

### 三条必须实现的技术约束（教师不感知）

| # | 约束 | 不做会怎样 |
| --- | --- | --- |
| 1 | 每个知识点导入时生成**稳定内部 ID**，学生状态绑 ID 不绑名字 | 教师改一个措辞，全班历史证据丢失 |
| 2 | 重新导入做**差异比对**：新增 / 改名 / 删除分别处理，删除只做**停用**不物理删除 | 期中调整清单会带走半学期证据 |
| 3 | 清单是**教师私有副本**，可"复制他人清单"作为起点 | 同校教师互相覆盖 |

### 这个方案的代价（需要接受）

- 跨教师、跨学校的知识点**无法自动对齐**，因此校级横向对比、跨班共享题库匹配在首期做不了。可接受 —— 首期本来就是教师个人工作台。
- 教师上传清单的**颗粒度会参差不齐**（有人一个单元 3 条，有人 15 条）。矩阵的分布条与提示要对颗粒度不敏感，不要出现"知识点太少所以显示不好看"。
- 需要准备 **3–5 份现成清单**（人教三上/三下等）供教师一键套用，否则冷启动第一分钟就卡住。这不算内容运营，只是种子模板。

## 9. 数据模型的对应修订

基于 v0.3 第 15 节，v0.4 需要改动：

## 10. 本轮待你拍板的六个问题

1. **教学视图作为矩阵默认视图**，你是否认同？（这是与 v0.3 差异最大的一处）
2. **置信度分流**是否可接受？它意味着教师并没有逐题看完所有 AI 输出 —— 但这是唯一能让确认流程活下来的方式。

4. **个性化提升项活跃数上限 5** 是否太硬？可改为软提示。
5. 知识清单方案改为教师上传后，是否仍需准备 **3–5 份种子模板**？我建议需要。
6. MVP 是否按建议收窄为：**知识清单导入 + 知识矩阵 + 课堂快速打点 + 单份作业 AI 分析 + 补差生成**，把个性化提升项与复测闭环推到下一阶段？

## 11. 下一步建议

1. 找 **3 位真实小学数学教师**，只用原型走两个任务：①把自己的知识清单导进来；②确认一份 12 人的 AI 分析。计时并记录卡点。
2. 优先做**导入 + 矩阵 + 快速打点**三件事的可用版本，不接 AI，让教师用两周。若两周后矩阵是空的，说明产品假设有问题，此时还没花 AI 的钱。
3. 合规先行：未成年人个人信息（作业图片 + 姓名）在《个人信息保护法》第 31 条下需监护人同意，教师个人上传全班作业的授权链是断的。上线前需明确"受学校委托处理"定位、图片留存期限、班内编号 + 本地姓名映射。建议正式落地前取得专业法律意见。
