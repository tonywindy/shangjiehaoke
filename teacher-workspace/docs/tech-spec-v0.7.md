## 0. 相对 v0.6 的变更

| # | 变更 | 原因 |
| --- | --- | --- |
| 1 | **BYOK 整节作废**，产品内不含任何 AI 代码、API Key、模型商对接 | 出题改为「生成 prompt → 教师去外部 AI → 粘回来」，无需接入 |
| 2 | **合规链条整体消失**，不再有未成年人信息出境问题 | 复制出去的是「知识点 + 错因 + 年级」，不含任何学生信息 |
| 3 | 证据对象从 9 字段瘦到 **5 字段**，`evidences` 更名 `judgements` | 只有一种来源时，来源类型／强度／确认人全是空转 |
| 4 | 四态砍到 **三态**，去掉「基本掌握」 | 教师要的是「是否掌握」，第三档以后随时能加，它只是显示层 |
| 5 | 「空」不再是一个状态值，而是**没有记录** | 最诚实的表达：这个格子没被判断过 |
| 6 | 题库从「模板 + 变式引擎」改为**整坨文本存档，不解析** | 每个 AI 输出格式不同，教师还会手改，解析必然失败 |
| 7 | 不做：证据强度、前置依赖、FSRS 复测排期、个性化提升项、家长版评价 | 全部推到二期，见 §7 |

## 1. 第一版是什么

三件事，一句话说完：

```
导知识点  →  点格子(✓/✕/空 + 一句话)  →  红叉点开：复制 prompt / 粘回来 / 存题库
     ↑                                                            │
     └──────────────── 用完回来改状态 ←───────────────────────────┘
```

**验证的假设只有一个：教师愿不愿意持续维护一张知识表。**

判据很硬：让教师用两周。两周后表是空的，假设就是错的。而此时代码里没有 AI、没有图片上传、没有合规风险，成本接近于零。

## 2. 数据模型（全部）

五张表。这就是第一版的完整数据模型。

```sql
-- 知识点：教师自己维护，随时增删改
CREATE TABLE kps (
  id          TEXT PRIMARY KEY,
  class_id    TEXT NOT NULL,
  unit_no     INTEGER NOT NULL,      -- 第几单元
  unit_name   TEXT,
  name        TEXT NOT NULL,
  sort_order  INTEGER NOT NULL,
  created_at  INTEGER NOT NULL,
  archived_at INTEGER                -- 软删除，历史判断不受影响
);

CREATE TABLE students (
  id       TEXT PRIMARY KEY,
  class_id TEXT NOT NULL,
  name     TEXT NOT NULL,
  seat_no  INTEGER
);

-- 判断：核心表，只追加不修改
CREATE TABLE judgements (
  id         TEXT PRIMARY KEY,
  student_id TEXT NOT NULL,
  kp_id      TEXT NOT NULL,
  status     TEXT NOT NULL,          -- mastered | needs_support
  note       TEXT,                   -- 可选，一句话。出题时它是关键输入
  judged_at  INTEGER NOT NULL
);

CREATE INDEX idx_j ON judgements(student_id, kp_id, judged_at DESC);

-- 题组：整坨文本，不解析
CREATE TABLE question_sets (
  id         TEXT PRIMARY KEY,
  kp_id      TEXT NOT NULL,          -- 按知识点归档
  title      TEXT NOT NULL,          -- 自动生成，可改
  error_tag  TEXT,                   -- 出题时用的那句错因
  content    TEXT NOT NULL,          -- 教师粘贴的原文，原样保存
  created_at INTEGER NOT NULL
);

-- 使用记录：闭环的那一环
CREATE TABLE question_set_uses (
  id         TEXT PRIMARY KEY,
  set_id     TEXT NOT NULL,
  student_id TEXT NOT NULL,
  used_at    INTEGER NOT NULL
);
```

三个要点：

**`status` 只有两个值，「空」是没有行。**这不是省事，是准确——一个班 40 人 × 60 个知识点 = 2400 个格子，任何时刻大部分是空的。空必须表示「还没判断」，不能表示「不会」，否则开学第一天整张表全红，这张表就废了。

**`judgements` 只追加，不 UPDATE。**当前状态 = 该 (student, kp) 下 `judged_at` 最大的那行。代价是一个 `ORDER BY`，换来的是「这孩子是什么时候转绿的」——期末写评语时你会需要它。

**`note` 是可选的一句话，但它是整个出题环节的燃料。**教师点红叉时随手写的「竖式对位错」，直接决定了 §5 生成的 prompt 质量。产品里要让它填起来足够顺手（默认聚焦、回车即存），但绝不强制。

## 3. 知识点导入

平台不预置任何教材版本。理由：版本归纳不完，科目各不相同，就算同版本每位教师的分类也不同。

**两条录入路径，都必须有：**

- **Excel / CSV 上传**：两列（单元、知识点名）即可，认列步骤要能容错
- **直接手打**：单元名 + 每行一个知识点，粘贴一段文本自动按行拆分

第一次打开产品会面对空清单，所以**准备 3–5 份种子清单**（人教三上／三下等）供一键套用后再改。这不是内容运营，是冷启动的必需品。

**知识点随时可增删改。**改名不影响历史判断；删除是软删除（`archived_at`），矩阵里不再显示，但历史记录仍可查。这条自由度是本产品的立身之本，不能有任何折扣。

## 4. 矩阵与判断

### 4.1 主视图

学生为行、知识点为列。三种显示：

| | 含义 | 视觉 |
| --- | --- | --- |
| 空 | 还没判断 | 灰色空格，**不计入任何百分比** |
| ✕ | 判断了，没掌握 | 红 |
| ✓ | 判断了，掌握了 | 绿 |

按单元切换，一次只看一个单元的知识点——**这是宽表不横向滚动到不可用的关键**（Canvas Learning Mastery Gradebook 的经典失败）。

### 4.2 点格子

单击直接切换 `空 → ✓ → ✕ → 空`，即点即存，不要弹窗、不要保存按钮。

切到 ✕ 时，格子下方就地展开一个单行输入框，填错因，回车即存，Esc 跳过。**不填也完全能用。**

### 4.3 两种批量入口

- **按知识点**：点列头 → 座位表 → 点掉没掌握的学生。课上 3 秒一次全班评价。
- **按学生**：点行头 → 该生本单元所有知识点一屏，键盘上下移动、空格切换。批作业时用。

### 4.4 列头统计

每个知识点列头显示 `8 ✕ / 21 ✓ / 11 空`。

**不显示百分比。**分母是「已判断人数」还是「全班人数」在教师那里有歧义，写个数字比写个会被误读的比例诚实。

## 5. 题库与出题

### 5.1 定位

教师自己也能打开豆包说「出三道有余数除法的题」。我们凭什么存在？

**因为上下文在我们这里，不在他脑子里。**他自己打字只写得出「有余数除法」；我们知道的是三年级、这孩子的问题是竖式对位错、班上还有 8 个人同样卡在这。这些拼进 prompt，出来的题不是一个东西。

我们不是 AI 产品，是**教师的上下文管理器**。AI 在外面随便换，模型商倒闭、涨价、换代都与我们无关。

### 5.2 三步

**① 生成 prompt，一键复制**

单人版，从矩阵红叉点进去：

```
你是小学数学老师。请为三年级学生出 3 道练习题。

知识点：有余数除法
学生的具体问题：竖式对位错，商的位置写错

要求：
- 第 1 题最基础，直接针对上面的错误
- 第 2 题换数字巩固
- 第 3 题稍作变式
- 每题附答案和一句话解析
- 不要出现学生姓名
```

小组版，从列头「8 人待提升」点进去：把这 8 人的 `note` 去重后一并给出，让 AI 出一套覆盖多种错法的共同练习。

Prompt 模板可编辑，教师改完的版本记住，下次沿用。

**②教师去任何 AI 粘贴**——豆包、DeepSeek、Kimi、ChatGPT。我们不关心，也不维护列表，不做跳转链接（会过期）。

**③ 粘回来**

一个 textarea，标题自动填 `有余数除法 · 竖式对位错 · 7月27日`，可改。保存。

### 5.3 不解析

这是最容易做错的地方。会很想把粘回来的文本拆成结构化的题（题干／答案／解析）。**别做。**

每个 AI 的输出格式都不一样，教师还会手改两句，解析必然失败——**失败一次教师就再也不用了**。整坨存，要用的时候整坨调出来打印或抄。教师本来就是这么用的。

结构化留给二期，而且很可能永远不需要。

### 5.4 归档：按知识点

题组挂在 `kp_id` 上，不挂学生。

理由是复用：同一个知识点的题，明年、别的班、别的学生都还能用。学生那边只留一条 `question_set_uses` 记录指回来。

点开任何一个知识点，能看到「我为这个知识点攒过的所有题」，按时间倒序，标着错因。**用得越久越值钱——第二年开学，这个题库就是产品对这位教师最硬的锁定。**

### 5.5 闭环：用完回来改状态

每个题组带一个「用了这批题之后，谁改了状态」的入口。给张小雨用了 → 记一条 → 过几天孩子做完了 → 从这里直接跳回矩阵改格子。

**这一环不能省。**没有它，题库会变成一个只进不出的收藏夹，而收藏夹是产品坟场。

## 6. 明确不做

写下来是为了防止范围回弹：

- ❌ 任何 AI 代码、API Key、模型商对接
- ❌ 作业图片上传、图片识别
- ❌ 证据来源类型、证据强度、确认人
- ❌ 「基本掌握」第四态
- ❌ 题目结构化解析
- ❌ 知识点前置依赖、根因分析
- ❌ FSRS 复测排期
- ❌ 个性化提升项
- ❌ 家长版评价、期末评价生成
- ❌ 学生排名、任何评分
- ❌ 班级事务模块（第一大功能，本版不涉及）

现有的 `today.html` / `tasks.html` / `class.html` / `learning.html` 高保真原型需要按本文范围收窄，不是按原型实现。

## 7. 二期怎么接（证明这版不是死路）

第一版是完整版的**最小子集**，不是需要推倒重来的临时方案。二期的每一项都是**加字段或加表，不改表**：

| 二期能力 | 改动 |
| --- | --- |
| 接 AI 作业分析 | `judgements` 加 `source` 字段，老数据默认 `teacher` |
| 证据强度 | 加 `strength` 字段，老数据给默认值 |
| 「基本掌握」 | `status` 加一个枚举值，显示层加个黄色 |
| 复测排期 | `judged_at` 已经有了，直接算 |
| 题目结构化 | `question_sets` 加子表，老数据不动 |
| 状态变化历史 | 已经有了——`judgements` 本来就只追加 |

所以「先做简单版，以后推倒重来」的风险不存在。**AI 天生长在接口外面，因为第一版里它根本不存在。**
