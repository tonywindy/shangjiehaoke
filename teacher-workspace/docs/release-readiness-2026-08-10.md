# 教师工作台上线前审查

审查日期：2026-08-10
审查范围：教师工作台前端、Cloudflare Worker 授权接口、Cloudflare D1 授权库、主站入口。

## 结论

核心流程已跑通，可以进入小范围邀请试用。上线前仍需要完成一次正式前端部署，并在正式域名上用一枚测试授权码做一次注册—登录—退出回归；测试完成后立即撤销测试授权码并删除测试账号。

## 已通过项目

- 主站构建成功，教师工作台的介绍页、账号页、条款页、今日、任务、班级、学情、回顾导出及管理后台均纳入构建入口。
- Cloudflare Worker 的 `AUTH_DB` 独立绑定已部署，旧 AI 接口使用的 `DB` 未改动；两个健康检查均返回正常。
- 授权码注册、登录、退出、续期、停用、账号禁用/恢复、管理员重置密码、首次登录强制改密均已通过接口回归。
- 同一授权码并发注册具有原子性，只会成功一次；错误 Origin 会被拒绝；会话使用 HttpOnly Cookie，并设置了有效期和退出清理。
- 管理员初始账号只在 Cloudflare Secret 与 D1 中使用，仓库中没有初始密码、哈希或密钥。首次登录必须修改密码。
- 体验版会使用单独的本机数据库、12 名虚拟学生和一个体验班；网络故障或授权服务不可达时不会静默切换到体验数据。
- 授权账号按账号 ID 隔离本机 IndexedDB；导出/恢复前做格式校验，当前班级恢复采用单事务写入。
- 主站已增加教师工作台入口，账号页明确说明本机优先保存、可选端到端加密云同步、恢复码责任和清除浏览器数据的影响。
- 浏览器点验确认：注册表单含协议勾选、首次改密拦截有效、后台未授权访问会回到账户改密页、体验版只显示一个体验班，新增班级会弹出授权提示。

## 发布前必须做

1. 先部署包含本目录全部前端文件的正式静态站点，再打开 `/teacher-workspace/account.html` 和 `/teacher-workspace/admin.html` 检查正式域名下的跨子域 Cookie。
2. 使用临时授权码完成一次真实域名注册回归，确认注册后能进入今日页；完成后在管理后台撤销该授权码、禁用并删除测试账号（如需保留审计记录则至少禁用并清理会话）。
3. 用管理员账号首次登录后立即改成独立长密码，并在密码管理器中保存；不要把初始密码发到群聊或写入仓库。
4. 在 Cloudflare 控制台保留 D1 迁移记录，并定期导出授权库备份；发布前确认 `AUTH_DB` 和旧 AI 的 `DB` 不是同一个库。
5. 配置售后处理方式：授权码补发、账号人工重置、退款/停用规则和隐私说明需要与实际销售页面保持一致。

## 已知限制与处理建议

- 教学数据优先保存在浏览器本机；会员可主动开启端到端加密云同步。新设备需登录同一账号并输入一次恢复码，未开启同步时仍需通过备份文件迁移。
- 当前没有自动支付、短信/邮件验证码和自动续费；采用私信发授权码时，应建立授权码台账和人工售后流程。
- 体验版的限制属于前端功能门控；正式售卖时应把“体验版开放项”和“授权版开放项”写在介绍页，不能把它当作服务端的强安全边界。
- 多班级批量恢复不是跨数据库事务，页面会提示可能部分完成；建议恢复前先导出一次当前数据。
- `npm audit` 仍报告 React Router 的 RSC 模式告警。本项目只使用普通 `BrowserRouter`，没有启用 RSC；本次不强行降级依赖，后续升级到有正式修复的版本后再关闭该例外。
- 生产前端部署尚未由本审查自动完成；GitHub 分支推送和站点构建完成后，必须按第 1、2 项再做一次线上回归。

## 管理员入口

正式部署后访问：`/teacher-workspace/admin.html`。未登录或首次改密未完成时，会自动回到账户页；完成改密后才可进入授权码和用户管理。
